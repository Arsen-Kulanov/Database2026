The entity-relationship database schema models airport and flight management across ten entities. The Airports entity uses the primary key airport_id and includes attributes airport_name, country, state, city, created_at, and updated_at. The Airlines entity uses airline_id as its primary key, alongside airline_code, name, country, created_at, and updated_at. These two entities connect to the Flights entity, which is identified by primary key flight_id and contains foreign keys departure_airport_id and arrival_airport_id referencing Airports, as well as airline_id referencing Airlines. The Flights entity also tracks operational attributes: departing_gate, arriving_gate, scheduled_departure_time, actual_departure_time, scheduled_arrival_time, actual_arrival_time, created_at, and updated_at.

Passenger management is handled through the Passengers entity, identified by passenger_id and containing personal information including first_name, last_name, gender, date_of_birth, country_of_citizenship, country_of_residence, passport_number, created_at, and updated_at. Reservations are recorded in the Bookings entity with primary key booking_id, linking to Passengers via foreign key passenger_id and to Flights via foreign key flight_id. Bookings contains operational metadata including status, booking_platform, ticket_price, created_at, and updated_at.

Several entities connect directly to Bookings. The boarding_passes entity uses primary key boarding_pass_id, links to booking_id as a foreign key, and stores boarding_time, seat, created_at, and updated_at. The Baggage entity uses primary key baggage_id, references booking_id as a foreign key, and contains weight_in_kg, created_at, and updated_at. The booking_changes entity tracks reservation modifications using primary key change_id, references foreign key booking_id, and stores status, created_at, and updated_at.

Security and screening events are stored in two separate entities. The Baggage_checks entity uses primary key baggage_checking_id, connects to both booking_id and passenger_id via foreign keys, and contains check_results, created_at, and updated_at. The Security_checks entity uses primary key security_check_id, references passenger_id as a foreign key, and records check_results, created_at, and updated_at.
